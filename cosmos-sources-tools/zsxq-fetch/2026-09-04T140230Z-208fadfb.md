## Why the change was needed

Topic links were routed to a dedicated platform-detail parser instead of the general webpage extraction flow. A linked topic could fail with DETAIL_ROOT_MISMATCH while collection of the requested timeline succeeded. The requested behavior is to treat every topic URL as a linked webpage.

## Reproduction

1. Collect a requested timeline containing a link to another topic.
2. The previous instructions selected collectZsxqDetailOnTab for that link.
3. A detail DOM mismatch stopped extraction of the linked topic. The exact original DOM mismatch was not established.
4. Read the same linked page through the general webpage helper: in this validation, the clean-webpage CLI returned no body and the signed-in browser returned readable topic text.

## Changed packaged paths

- `skills/zsxq-fetch/SKILL.md`: every link, including platform topic links and short links, uses the existing clean-webpage-first flow.
- `skills/zsxq-fetch/references/runner-contract.md`: remove detail APIs; document unified linked-page handling and one-hop file boundaries.
- `skills/zsxq-fetch/scripts/zsxq-browser-collector.mjs`: remove detail inventory, expansion, access checks, downloads, and detail selectors; update contract v12 to v13. Timeline and direct-attachment download implementations remain unchanged.

Source-worktree supporting additions: `tests/zsxq-linked-pages.test.mjs`, `ARCHITECTURE.md`, `CHANGELOG.md`, `GOTCHAS.md`, and `DECISION.md`. These are source-controlled material rather than generated artifacts; the existing ignore rules remain sufficient.
