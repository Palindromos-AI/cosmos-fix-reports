## Why the change was needed

An official PDF, HTML, or Word download left its file-preview overlay open. A later attachment in the same tab could then fail preview identity matching or navigate to a Chrome-blocked file-host page instead of opening the intended file card; the expected behavior is to restore and prove the source page after every attempt.

## Reproduction

1. In an authenticated Knowledge Planet timeline, open a supported file card and use the visible official download control.
2. Without closing the resulting preview overlay, try another supported file card in the same tab.
3. Observe that the second action can remain bound to stale preview state or navigate to a blocked file-host page.

## Changed packaged paths

- `.codex-plugin/plugin.json`: advance the plugin version to 0.20.3.
- `skills/zsxq-fetch/SKILL.md`: document that the downloader owns preview dismissal and source-page verification.
- `skills/zsxq-fetch/references/runner-contract.md`: document the v12 preview lifecycle and failure semantics.
- `skills/zsxq-fetch/scripts/zsxq-browser-collector.mjs`: click the preview backdrop outside its content in a `finally` path, then verify preview absence, unchanged URL, and the source-page root.
