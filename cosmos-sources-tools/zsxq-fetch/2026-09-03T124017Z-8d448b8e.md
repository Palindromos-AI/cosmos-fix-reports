## Why the change was needed

The live file-card DOM no longer exposes the previously required `data-file-id` attribute in either an owner-controlled planet or an ordinary member planet. File inventory therefore stopped before official downloads even though the visible publication time, filename, and file type remained available.

## Reproduction

1. Open either authenticated planet timeline containing a PDF, HTML, or Word file card.
2. Run the v10 timeline collector.
3. Observe `FILE_ATTACHMENT_MISMATCH` with no stable file ID despite a visible filename and publication time.

## Changed packaged paths

- `skills/zsxq-fetch/scripts/zsxq-browser-collector.mjs`: removed the absent file-card ID requirement, matched one file by exact publication time and filename, validated its extension against the expected file type, and bumped the browser contract to v11.
- `skills/zsxq-fetch/references/runner-contract.md`: documented the v11 identity rule and its fail-closed behavior for zero or multiple candidates.

## Diff

```diff
- version: "zsxq-web-angular-v10"
+ version: "zsxq-web-angular-v11"
- require one stable file-card platform ID
+ require exactly one publication-time and exact-filename match
+ require the filename extension to match the expected PDF, HTML, or Word type
+ fail only that file when zero or multiple candidates remain
```
