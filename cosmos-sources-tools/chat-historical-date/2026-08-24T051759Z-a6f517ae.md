## Why the change was needed

The two desktop group collectors only accepted the current Beijing day. A day with no new messages could verify empty-day traversal but could not exercise source extraction against an earlier calendar day.

## Reproduction

1. Request one past Beijing calendar day from either desktop group collector.
2. Observe that the original contract derives the date only from the current run cutoff and offers no historical-date input.
3. The expected behavior is one optional strict non-future Beijing date, with the existing current-day behavior preserved when the date is omitted.
