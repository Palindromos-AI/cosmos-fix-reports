## Why the change was needed

Generated outputs used inconsistent flat or run-versioned layouts, so same-day refreshes could create redundant history or overwrite ambiguously. The expected behavior is one Beijing-date directory, stable source-specific identity independent of natural-language rewording, atomic same-identity refresh, coexistence for different identities, and complete-result protection.

## Reproduction

Run a source writer twice for one Beijing date and logical scope, then repeat with an equivalent rewording and with a materially different scope. Before the repair, chat outputs retained run-ID snapshots, source identities depended on raw wording, ZSXQ display-name changes broke identity, and concurrent CLS writers could allow an older snapshot to win.
